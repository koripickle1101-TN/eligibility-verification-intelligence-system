01

Eligibility Exception Closure Rule™

An eligibility exception is not considered resolved when it is identified. It is resolved only after the exception is documented, assigned to clear ownership, acted upon, and its closure is confirmed before the workflow advances.

Required workflow Detect → Document → Assign → Act → Verify → Close → Advance

Trigger: Eligibility verification identifies a coverage, benefits, patient-responsibility, referral, authorization, demographic, payer-selection, coordination-of-benefits, or other unresolved exception.

02

Exception Ownership & Closure Control™

The purpose of this control is to prevent a detected exception from silently traveling downstream without documented ownership and verified resolution.

Control-gate question Before this case moves forward, is every eligibility exception documented, assigned, acted on, and verified as resolved?
Control-gate principle

A completed checkpoint is not the same as a controlled workflow state.

A workflow may look complete at one checkpoint while an unresolved condition is still moving downstream. EVIS treats that gap as an operational control problem that requires visible ownership, evidence, and verified closure before advancement.

Operational distinctions Detection ≠ Resolution · Handoff ≠ Ownership · Advancement ≠ Readiness · Closure ≠ Assumption
If no

Hold · Route · Escalate

The workflow remains in an exception state until the unresolved issue has a defined next action and meets the modeled closure requirements.

If yes

Advance

The case can move to the next modeled workflow step only after closure is documented and verified.

EVIS Status Logic

The status model separates detection, ownership, active resolution, escalation, closure verification, and readiness for the next workflow step.

06

Portfolio Insight — Detection ≠ Resolution

An eligibility workflow can successfully detect an issue and still fail operationally if the exception is not owned, acted on, and closed.

The operational question is not only “Was eligibility verified?” It is also: “What happened to every exception the verification process uncovered?”

Healthcare Operations Intelligence Engine™ Where did the workflow first lose control?

Key learning: The first control failure may not be the original eligibility problem. It may occur after the problem was correctly identified but before anyone ensured it was resolved.
